# 清理、专用数据域reset与轮末兜底

## 选择清理依据

共享环境默认按intent、准确ID及owned证明清理。用户明确授权某个独占数据域整体清空时，该域获准资源可改用当前完整盘点证明删除范围，不要求逐条补齐历史创建receipt；原创建结果unknown也可纳入。授权须对应实际环境、准确租户/数据域、允许清空的资源类型、保护基线及有效范围。已有明确授权直接复用；名称包含“测试”、账号是管理员、数据看似自动生成或某次测试失败均不证明独占。

resource kinds按用户授权列举，不固定为某几类。授权可覆盖业务实体，也可覆盖临时组织、角色、人员及授权关系；默认根组织、默认超管和管理员继续测试所需最小权限/应用授权作为保护基线，其他保护项按用户范围固定。reset仅覆盖回读确认的隔离域及获准kind，不扩展到其他scope。tenant0属于共享元数据域，禁止reset，仅按准确owned证据清理获准的专用记录。其他共享域同样保留owned门禁。专用域内的共享配置仍按原snapshot恢复，不随业务数据reset删除。

## 执行与恢复

复用项目runner、cleanup_state及独立恢复journal，不新增通用reset框架或默认开关。清理执行属于原范围的恢复动作；相关普通case写派发保持残留门禁，不能靠新run或修改scope绕过。

1. **固定授权与边界**：保存用户授权引用、脱敏origin、准确tenant/data scope、获准kind、保护基线清单及原证据hash。通过真实认证身份和服务响应确认租户/组织归属，逐项排除保留的基线账号、应用、授权关系及用户指定资源。身份、枚举完整性或资源归属不能核实时暂停受影响域；不要求用旧receipt代替已授权域的当前完整盘点。
2. **停源与互斥**：停止相关case派发及其他会修改目标数据域的任务，收敛在途请求；同一环境/租户/数据域取得跨worker、进程和runner互斥，保持至最终核验。
3. **先完整盘点再删除**：按真实API契约枚举全部获准kind，包含测试创建unknown及历史遗留，不以名称前缀缩小范围。逐页校验HTTP与业务status、响应shape、tenant/组织身份、准确ID唯一性、total/游标完整性及终止条件；空页但未达total、重复/跳页、总数漂移或达到页数上限均为未完成。完整ID集合与分页凭据先持久化，再按固定集合删除；禁止边删边按offset翻页造成漏项。仅有稳定游标契约且能证明无遗漏时可用对应方式。无完整枚举接口或可见性不足时保持未决。
4. **逆依赖与分支容错**：按实际引用图先清理子资源，解除引用后再处理相应父项；具体顺序由应用引用决定，不从类型名称猜。一个分支失败保留该分支及受依赖父项，继续已证明无依赖且安全的其他分支。未知API契约、权限拒绝或相同业务错误转诊断；仅在确认可重试且输入/环境有变化或合法退避条件下有界重试，不无限重发DELETE。
5. **逐项核验与轮末sweep**：写响应同时校验HTTP及业务status，成功回执不等于absence。完成后以独立scope sweep重新完整枚举所有获准kind、准确租户及相应运行时数据义务，保存零集合、分页完整性、停源/互斥和身份回读。逐case cleanup是日常第一层；每轮收尾独立sweep是兜底，两者均实际执行。新盘点发现遗漏时在同一授权及互斥内继续处理；数据持续增长则修复生产者，不把循环扫描当作成功。
6. **真实不能删除**：应用不支持删除或存在无法解除的真实引用时，按原授权恢复基线、放回复用池或禁用并回读，登记retained及原因；满足原保留契约后才能记retained_verified。baseline存在不是本应删除的未引用资源的清理证明。保留项、失败项及未决项分别报告；任一获准删除集合非零都不报告“已清空”。保护基线不纳入要求归零的删除集合；混合kind须完整枚举后按准确ID区分保护项和获准删除项，不能用过滤掩盖残留。

中断前后均保留原盘点、进度、写回执、absence、retained及错误证据。恢复重新核验授权范围、身份、停源、互斥及当前完整盘点，已缺席项跳过写入，未决项按新读回继续；不重试原unknown创建，不改原账本，不改已被计划/journal引用的review，使用新sidecar与hash关联原件。

## scope absence与跨run残留

只有在相同稳定环境、准确租户/数据域、授权kind内，停源后完整枚举的获准删除集合全部归零、保护基线已回读且相关运行时义务已核验，才形成scope absence；单个GET为空、一次test passed、列表第一页为空、仅禁用或部分kind归零都不满足。scope证明须保存授权引用、原件hash、盘点时间/身份/分页来源、停源证据、逐kind零集合、保护基线及未决/保留项，不能将一个专用域的证明套用tenant0或其他租户。

adapter将该证明映射到确实落入此scope的原unknown/残留义务，并实际调用现有cleanup_state接口；准确ID资源继续按原environment+kind+id提交匹配的absence_verified及来源证据。unknown没有服务端ID时，保留原操作/义务的稳定关联，使用原adapter支持的义务标识，不能编造物理ID或把intent候选当作成功创建。未知原scope、跨租户、共享资源、授权外kind或运行时义务未核完者继续阻断。

索引逐项关闭并回读核实，保留旧journal和结案来源；禁止静默清空/删索引、批量unblock或重写历史状态。现有adapter若不能表达scope证明到原义务的可靠映射，就保留阻塞并补接入，不声称工具原生支持scope reset、未执行桥接却宣称已解除。retained_verified与absence分别统计；存在保留项时不能以scope清空结案。
