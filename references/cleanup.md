# 清理、专用数据域reset与轮末兜底

## 选择清理依据

共享环境默认按intent、准确ID及owned证明清理。用户明确授权某个独占数据域整体清空时，该域获准资源可改用当前完整盘点证明删除范围，不要求逐条补齐历史创建receipt；原创建结果unknown也可纳入。授权须对应实际环境、准确租户/数据域、允许清空的资源类型、保护基线及有效范围。已有明确授权直接复用；名称包含“测试”、账号是管理员、数据看似自动生成或某次测试失败均不证明独占。

resource kinds按用户授权列举，不固定为某几类。保护基线由用户确认，包含继续执行获准测试所需的身份、权限和其他保留项，以准确ID及回读固定，不预设组织层级或管理员角色。reset仅覆盖回读确认的隔离域及获准kind，不扩展到其他scope。共享/系统数据域由项目配置及实际归属确认，禁止reset，仅按准确owned证据清理获准的专用记录，不以域名或ID推定独占。专用域内的共享配置仍按原snapshot恢复，不随业务数据reset删除。

## 执行与恢复

复用项目runner、cleanup_state及独立恢复journal，不新增通用reset框架或默认开关。清理执行属于原范围的恢复动作；相关普通case写派发保持残留门禁，不能靠新run或修改scope绕过。

1. **固定授权与边界**：保存用户授权引用、脱敏origin、准确tenant/data scope、获准kind、保护基线清单及原证据hash。通过真实认证身份和服务响应确认租户/组织归属，逐项排除保留的基线账号、应用、授权关系及用户指定资源。身份、枚举完整性或资源归属不能核实时暂停受影响域；不要求用旧receipt代替已授权域的当前完整盘点。
2. **停源与互斥**：停止相关case派发及其他会修改目标数据域的任务，收敛在途请求；同一环境/租户/数据域取得跨worker、进程和runner互斥，保持至最终核验。
3. **先完整盘点再删除**：按真实API契约枚举全部获准kind，包含测试创建unknown及历史遗留，不以名称前缀缩小范围。逐页校验HTTP与业务status、响应shape、tenant/组织身份、准确ID唯一性、total/游标完整性及终止条件；空页但未达total、重复/跳页、总数漂移或达到页数上限均为未完成。完整ID集合与分页凭据先持久化，再按固定集合删除；禁止边删边按offset翻页造成漏项。仅有稳定游标契约且能证明无遗漏时可用对应方式。无完整枚举接口或可见性不足时保持未决。
4. **逆依赖与分支容错**：按实际引用图先清理子资源，解除引用后再处理相应父项；具体顺序由应用引用决定，不从类型名称猜。一个分支失败保留该分支及受依赖父项，继续已证明无依赖且安全的其他分支。未知API契约、权限拒绝或相同业务错误转诊断；仅在确认可重试且输入/环境有变化或合法退避条件下有界重试，不无限重发DELETE。
5. **逐项核验与轮末sweep**：写响应同时校验HTTP及业务status，成功回执不等于absence。完成后以独立scope sweep重新完整枚举所有获准kind、准确租户及相应运行时数据义务，保存零集合、分页完整性、停源/互斥和身份回读。逐case cleanup是日常第一层；每轮收尾独立sweep是兜底，两者均实际执行。新盘点发现遗漏时在同一授权及互斥内继续处理；数据持续增长则定位写入来源，修复测试侧生产者或停止原授权内任务；业务侧问题登记报告，修改另依授权，不把循环扫描当作成功。
6. **真实不能删除**：应用不支持删除或存在无法解除的真实引用时，按原授权恢复基线、放回复用池或禁用并回读，登记retained及原因；满足原保留契约后才能记retained_verified。baseline存在不是本应删除的未引用资源的清理证明。保留项、失败项及未决项分别报告；任一获准删除集合非零都不报告“已清空”。保护基线不纳入要求归零的删除集合；混合kind须完整枚举后按准确ID区分保护项和获准删除项，不能用过滤掩盖残留。

中断前后均保留原盘点、进度、写回执、absence、retained及错误证据。恢复重新核验授权范围、身份、停源、互斥及当前完整盘点，已缺席项跳过写入，未决项按新读回继续；不重试原unknown创建，不改原账本，不改已被计划/journal引用的review，使用新sidecar与hash关联原件。

恢复按项目实际契约分阶段持久化：资源清理、适用的运行时义务、租约释放和残留索引对账分别保存实际结果，不强制所有项目具有相同阶段。中途失败先读journal，只补尚未完成且当前证据支持的动作；按准确资源及义务区分absence、retained和未决，某一阶段成功不代表其余阶段已完成。证据已按正常流程销毁时，核对仍未完成义务所需的真实证据，不因此重开已结案资源，也不为汇总失败重复已有副作用。

完成恢复后，后续汇总将不可变原账本与独立恢复overlay合并；再次桥接同一历史账本时，按稳定义务标识识别已核验结案来源，避免重复登记已关闭残留。索引关闭必须仍有匹配证据，不能通过忽略旧账本或批量解除门禁实现。

## 组合fixture的失败收尾

初始化开始即登记资源与清理句柄，取得准确创建回执后立即落账，不等整个prepare成功再注册teardown。部分初始化失败也必须进入清理；同一资源可以被多个fixture引用，但不能因此重复计数或重复删除。

- 组合清理按实际依赖图逐分支收敛：删除失败只冻结仍被引用的资源及其依赖，已证明安全独立的准确owned资源继续清理。共享槽位按各自义务冻结/释放，不因一个分支异常跳过整个finally或释放全部槽位。
- 保留首个具体清理失败及后续错误链，不能只输出cleanup_incomplete等汇总异常。每个安全独立分支在finally中落账并尝试收尾；只有真实依赖尚未解除的分支保持冻结，异常聚合后仍让runner完成原生结果采集及残留登记。
- 独立sweep覆盖本轮实际使用的全部规范账本kind及运行时义务，不能只检查传统resource-ledger。runner打印owned=0、部分账本全absence或业务全部通过，不代表没有其他资源、会话、共享配置或消息义务。报告分别列账本数、去重后的资源数及义务数；无法可靠去重时不报物理资源总数。
- **新增记账结构同步接入审计**：fixture增加子资源或操作账本时，同步维护规范扫描、恢复overlay和跨run残留桥接，覆盖未知创建、部分初始化失败及级联删除后的准确absence。遇到无法识别的结构保留未决及诊断，不按零资源处理；离线验证未知操作会进入残留门禁、匹配回读才能关闭。新增字段不用于追认旧轮次缺失的创建证据。
- CLI正常结束、初始化失败和受控中断均由runner收尾入口同步规范账本到[跨run残留索引](checkpoints.md#跨run残留门禁)，保留每个清理步骤的错误，同时继续安全独立分支。修复清理代码以受影响fixture离线回归验证，再在下一批获准增量执行中用规范审计与独立sweep验证，不为清理验证重跑全部业务。

## scope absence与跨run残留

只有在相同稳定环境、准确租户/数据域、授权kind内，停源后完整枚举的获准删除集合全部归零、保护基线已回读且相关运行时义务已核验，才形成scope absence；单个GET为空、一次test passed、列表第一页为空、仅禁用或部分kind归零都不满足。scope证明须保存授权引用、原件hash、盘点时间/身份/分页来源、停源证据、逐kind零集合、保护基线及未决/保留项，不能将一个专用域的证明套用共享/系统域或其他租户。

adapter将该证明映射到确实落入此scope的原unknown/残留义务，并实际调用现有cleanup_state接口；准确ID资源继续按原environment+kind+id提交匹配的absence_verified及来源证据。unknown没有服务端ID时，保留原操作/义务的稳定关联，使用原adapter支持的义务标识，不能编造物理ID或把intent候选当作成功创建。未知原scope、跨租户、共享资源、授权外kind或运行时义务未核完者继续阻断。

恢复闭环同时核对三层：实际实体与运行时义务、不可变原账本加独立恢复overlay、跨run残留索引。overlay按准确义务关联原件hash、实际回读及恢复阶段；实体已清但索引仍pending时，仅补证据映射和cleanup_state对账，不重跑业务、不再次删除。再次导入旧账本也复用此结案来源，不把已关闭义务重新登记为pending。

索引逐项关闭并回读核实，保留旧journal和结案来源；禁止静默清空/删索引、批量unblock或重写历史状态。现有adapter若不能表达scope证明到原义务的可靠映射，就保留阻塞并补接入，不声称工具原生支持scope reset、未执行桥接却宣称已解除。retained_verified与absence分别统计；存在保留项时不能以scope清空结案。
